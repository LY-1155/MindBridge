# 合并 SenseVoice 推理：一次调用同时产出 ASR 文本和语音情绪标签

语音识别（ASR）和语音情绪分析在上线后都会默认使用 SenseVoice 模型。我们决定在 API 入口层只创建一次 SenseVoice 实例，一次 `generate()` 调用同时产出转录文本和情绪标签，而不是分开跑两次独立推理。

## 为什么

- SenseVoice 的 `generate()` 本身就同时输出文本和情绪标签（如 `<|sad|>`），拆分两次调用意味着对同一段音频跑两次一模一样的推理，无端浪费 GPU 时间。
- RTX 5070 的单次推理延迟足够低，不影响响应时间目标。合并后还将延迟减半。
- ASR 结果和情绪标签在管线中流向同一个情绪模块，不存在跨模块竞争问题。

## 考虑过的方案

- **拆开两次调用**：ASR 模块和田情绪模块分别持有各自的 SenseVoice 实例。优点是模块边界清晰，缺点是同一音频被推理两次，显存和延迟翻倍。不选。
