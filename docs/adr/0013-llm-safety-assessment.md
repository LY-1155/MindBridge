# ADR 0013: LLM 语义安全评估器参与危机判断

**状态**: proposed
**日期**: 2026-08-06
**关联**: 部分推翻 `ADR-0003` 的"LLM 不参与主决策"；设计详见 `docs/家庭模式对话/危机判定改造方案.md`

## 上下文

危机路由依赖关键词匹配判定风险。关键词枚举不完备导致两类问题：误伤（"狠狠"命中暴力红线打断优质治疗对话）与漏判（跨轮累积的风险无法用词表捕捉）。ADR-0003 规定"LLM 仅作为低置信度时的可选降级补充，不参与主决策"，以保证 crisis 路由可审计、可解释。

## 决策

在**安全评估层**（危机判定）引入 LLM 语义安全评估器，reopen ADR-0003 对该层的限制。LLM 参与判断"是否构成危机"，但受以下约束：

1. **规则锚点触发**：仅敏感词命中 / 情绪 risk 超低阈值 / SCID 标记时调用评估器，非每轮。
2. **显式危险信号（P0）保持规则硬闸门**：评估器不得将 P0 直接降级为无害。
3. **输出分级响应**：crisis / probe / no_risk。
4. **探针 LLM 生成、规则兜底**。
5. **高危→降级案例全部落日志进人审**，可审计性由评估器结构化输出 + 理由 + 上下文日志承担。

## 考虑过的方案

- **纯规则分级（P0/P1/P2 词表）**：仍受关键词枚举不完备约束，只是把维护压力换一种形式，拒绝。
- **每轮调用评估器**：成本与延迟全覆盖，作为锚点失效后的备选开关（`SAFETY_JUDGE_EVERY_TURN`），非主方案。
- **锚点触发评估器（选定）**：延迟与成本限于少数轮次，规则兜底保留安全下限。

## 后果

- 危机判断从"纯规则"变为"规则触发 + LLM 语义裁决"；ADR-0003 的"必须能说清原因"由日志 + 人审承担。
- 带锚点轮次首字延迟增加约 1 秒（评估器与前置阶段并行，已最小化）。
- 医生 persona 保持唯一说话声音，评估器静默（2-agent 边界），不引入额外说话 agent。
