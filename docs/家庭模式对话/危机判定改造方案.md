# 危机判定改造方案：LLM 语义安全评估器（Semantic Safety Judge）

> 日期：2026-08-06 | 状态：设计定稿，待实施
> 关联：`docs/adr/0013-llm-safety-assessment.md` | `docs/家庭模式对话/README.md`

## 一、问题

现状危机路由由**关键词匹配**驱动，存在两类系统性缺陷：

1. **误伤**：弱信号词直接触发危机模板，打断优质治疗对话。
   真实案例——用户说"我这时候很想大叫**狠狠**的撞东西，感觉身体上的一些疼痛好像会麻痹自己"，
   `SAFETY_RED_LINE["violence"]` 命中"狠狠"（[family_assessor.py:38-39](modules/assessment/family_assessor.py#L38-L39)），
   纯子串匹配直接 `escalation_flag=True` → 危机路由 → 用户收到危机模板，对话被硬生生掐断。
   其实用户只是在描述一种压抑的冲动（P2 弱信号），应该继续对话。

2. **漏判 + 维护黑洞**：关键词枚举永远列不完全。
   - 危险常常是**跨轮累积**的（厌学 → 被害感 → 家庭拒绝 → 不想活 → 自伤冲动），
     没有任何词表能列出"一个过程"。
   - 枚举不完备 → 今天修"狠狠"，明天冒"撞门"，词表永远在补，维护是无底洞。

**根因**：把"风险词命中"当成"危机判定"。风险词是**信号**，不是**判决**。

## 二、改造目标

1. **判断者换成 LLM**：语义理解取代关键词列举，消灭枚举黑洞。
2. **响应分级**：风险词命中不再直接打断对话，按危险程度分级反应。
3. **决策进一张图**：安全、情绪、路由、裁决统一到 LangGraph 一张图。
4. **医生保持唯一声音**：裁决器静默，用户始终只面对周医生。

## 三、核心设计（一句话）

> **风险词命中 ≠ 危机触发。风险锚点只负责"提醒"，LLM 语义安全评估器负责"判决"，
> 判决按危险程度分级反应，危机模板只在确认危险时使用。**

## 四、关键概念

| 术语 | 定义 | 详见 |
|---|---|---|
| **语义安全评估器** | 读最近若干轮对话上下文 + 规则信号，输出三级裁决（crisis / probe / no_risk）的 LLM 组件。静默运行，不面向用户。 | [CONTEXT.md](../../CONTEXT.md) |
| **风险锚点** | 规则层产出的"可能构成风险"的候选信号，是触发评估器的条件。故意设得宽松（宁可多调，不可漏掉）。 | 同上 |
| **分级响应** | 按裁决危险程度采取的分级动作：crisis → 危机模板 / probe → 医生对话+安全探针 / no_risk → 正常对话。 | 同上 |
| **安全探针** | 医生对话中嵌入的结构化风险确认问题（三选一框架），用于区分"念头"与"计划"。LLM 生成，规则兜底。 | 同上 |

## 五、目标框架结构（一张图）

```
                    ┌── stopped（P0 显式危险/blocked）→ [crisis_emotion_router] ──┐
[safety] ─条件边─┤                                                               ├──→ [intervention]
                    └── pass → [emotion] ──→ [router] ───────────────────────────┘
                                  └─→ [safety_judge] ──────────────────────────→  ┘
                                          （LLM 语义安全评估器，1~2 秒）
```

- **扇出**：`safety` 通过后，`emotion`（几百毫秒）与 `safety_judge`（1~2 秒）**并行**。
- **扇入**：`intervention` 等 `router` **和** `safety_judge` 都完成才开工（LangGraph 自动同步）。
- **短路**：P0 显式危险信号 / blocked 直接注入 crisis 路由，跳过评估器（安全优先，规则硬闸门）。

`run_pipeline_pre`（[orchestrator.py:252](pipeline/orchestrator.py#L252) 手写前置代码）删除，
改为走同一张图的前置节点，消除"两条路"历史遗留。

## 六、分级响应行为

| 裁决 | 反应 | 举例 |
|---|---|---|
| **crisis** | 危机模板（确定性话术，不走 LLM） | "我想买安眠药今晚就吃" |
| **probe** | 医生继续对话，prompt 注入安全探针 | "不活了算了" → 医生问："是真心不想活，还是心里难受？" |
| **no_risk** | 正常医生对话 | "狠狠撞东西"（弱信号，评估器驳回） |

**会话级状态机**（防"否认"糊弄 + 防漏判）：

```
NONE ──(P0)─────────────→ CRISIS
NONE ──(probe 裁决)─────→ PROBING ──(用户确认计划/手段)──→ CRISIS
                             ├─(否认/仅念头)──→ NONE（标记保留）
                             └─(多次 probe 复现)─→ CRISIS（累积升级）
```

## 七、锚点触发条件（评估器何时被调用）

满足**任意一条**即调用评估器；无锚点则直接走正常医生对话（零额外延迟）：

1. **安全敏感词命中**（自杀/自伤/暴力/非法词表）
2. **情绪 risk ≥ 低阈值**（默认 0.4，故意低于 crisis 阈值 0.7，宁可多调不可漏掉）
3. **评估器/SCID 风险标记**（跨轮累积 criteria、红线信号）
4. **会话历史有风险信号**（复现 → 直接升级，不再重复探针）

配置项 `SAFETY_JUDGE_EVERY_TURN`（默认 false）可切换为每轮调用，作为锚点失效后的备选开关。

## 八、流式路径处理（裁决先于流式）

**铁律：一旦开始流式，只能追加，不能撤销。** 发出去的 token 收不回，
所以影响"流什么"的裁决必须在开始流式**之前**完成：

```
带锚点的消息:
  前置阶段(0.3s) ──并行── 评估器(1~2s)
  → 等裁决:
      crisis   → 不流式，直接发危机模板
      probe    → 开始流式医生回复（探针注入下一轮 prompt）
      no_risk  → 开始流式医生回复
代价：仅带锚点轮次首字延迟 +约 1 秒（期间前端显示"正在思考"，chat.py:156 已支持）。
普通轮次零改动。
```

## 九、多角色边界（2-agent，不再加）

| 角色 | 说话 | 职责 |
|---|---|---|
| 医生 Agent（周医生） | ✅ 唯一声音 | 治疗对话，含安全探针 |
| 语义安全评估器 | ❌ 静默 | 语义风险判决，把结论交给医生 |

**不再加会说话的 agent**：监督 agent 冗余（router 已做）；危机专精 agent 有害（打断 persona 连续性）。
"专精"通过**同一声音换 prompt**（注入危机评估协议）实现，即现有 `probe_direction` 机制的延伸。
设计依据见 [README.md](README.md) 的"B 前台 + A 后台"架构决策。

## 十一、实施步骤（分阶段）

**阶段 1：裁决器组件**
1. 词表分级（P0 显式危险 / P1 探针 / P2 弱信号），统一三套词表来源
2. 写 `SafetyJudge`：prompt（读最近 N 轮对话 + 锚点信号）→ 结构化输出 `{verdict, risk_type, confidence, probe_suggestion}`
3. 兜底：LLM 超时/失败 → 按锚点强度降级（P0→crisis，P1→probe，P2→no_risk）

**阶段 2：图节点 + pre 并入图**
4. 图加 `safety_judge` 节点，与 `emotion` 扇出并行
5. `run_pipeline_pre` 改为走图（删除手写前置代码）

**阶段 3：流式三分支 + 探针注入**
6. `astream_intervene` 读裁决：crisis→模板 / probe→医生+探针 / no_risk→正常
7. 探针 prompt：LLM 按当前对话生成，规则给三选一框架兜底

**阶段 4：修误伤行为**
8. `SAFETY_RED_LINE` 删弱信号（"狠狠"等），P1 词转探针而非升级
9. `scid_tracker` `death_si` 改触发探针 + 会话级累积升级状态机

**阶段 5：测试 + 验证**
10. 单元测试：裁决器分级、探针生成、状态机、超时兜底
11. `verify_doctor_mode.py` 用"狠狠撞东西"等真实对话回归验证不再误伤

## 十三、风险与缓解

| 风险 | 缓解 |
|---|---|
| LLM 漏判真危机（false negative） | P0 规则硬闸门兜底；高危锚点用对抗式框架（"请证明这不是风险"）；高危→降级案例全部落日志进人审 |
| LLM 误报（false positive） | probe 只是多问一句，无害；crisis 要求"高置信 + 锚点"双条件 |
| 延迟（带锚点轮次 +约 1 秒） | 与前置阶段并行，最小化；前端"正在思考"状态已支持；可用 `SAFETY_JUDGE_EVERY_TURN=false` 控制范围 |
| 成本（额外 LLM 调用） | 锚点触发（非每轮）；用 flash 级模型 |
| 可审计性（撞 ADR-0003） | 评估器结构化输出 + 理由 + 上下文全部落日志；高危降级人审；决策记入 ADR-0013 |
