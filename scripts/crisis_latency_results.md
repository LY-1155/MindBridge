# 危机响应延迟基准（S3）

口径：响应 = 检测裁决后的确定性模板阶段（CrisisHandler.handle），不经 LLM/网络；
检测（LLM 语义安全评估器）有 LLM 延迟，不在本基准声称范围。

注意：B 的「session」= Redis 读 + 内存追加；本机 USE_DATABASE=false，MySQL 写未计入
（若开启，危机审计落库约增加毫秒级，不影响「不经 LLM」结论）。C 对照未含 RAG 检索
（生产普通回复还会加检索+重排+历史），故 C 是生产普通回复延迟的下界——短路对比偏保守。

| 测量 | mean | p50 | p95 | p99 | max | n |
|---|---|---|---|---|---|---|
| A 危机响应生成 handle() | 0.11ms | 0.08ms | 0.29ms | 0.55ms | 1.00ms | 500 |
| B 完整危机路由（已裁决后，未含 MySQL 写） | 0.40ms | 0.35ms | 0.69ms | 1.08ms | 1.18ms | 200 |
| C 对照 LLM 生成 | 28536.79ms | 28536.79ms | 34696.69ms | 35244.24ms | 35381.13ms | 2 |

- 短路对比：危机响应 vs LLM 生成 ≈ **256,812x**
